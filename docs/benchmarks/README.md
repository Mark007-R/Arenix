# Benchmarks

`report.md` and `results.json` are generated by the simulation runner from actual local runs:

```bash
cd backend
uv run python -m arenix.sim.runner --seeds 1-10 \
  --conditions independent,communicate,negotiate,negotiate_mem0,negotiate_r1 \
  --out ../docs/benchmarks/results.json --report ../docs/benchmarks/report.md
```

Every condition uses the same seeds and starting conditions (6 AI contestants, 7-minute matches,
Emerald Isle). Numbers in this folder are never edited by hand. Re-run the command to refresh them.

## How to read the current results

* **No LLM is involved.** The `negotiate*` conditions use the deterministic `HeuristicProvider`
  planner over the same agent protocol, gateway, validation and coordinator that an LLM strategist
  uses. Latency, tokens and cost are therefore near zero. The `llm` condition has **not
  been run**, because no API credentials were available while building this, so no LLM numbers
  are reported.
* **Shrine awakened** is the clearest coordination signal. It needs three contestants to channel
  within 10 s. Non-communicating bots succeed only by coincidence. Agents that agree a start time
  over `PLAN_PROPOSAL`/`ACCEPT` and wait at the shrine succeed far more often.
* **`negotiate_r1` reaches 0% formal plan acceptance yet still awakens the shrine.** With a
  1-round budget the server refuses every reply, but the heuristic planner commits to the announced
  time when it decides to join, whether or not its ACCEPT is delivered. This shows a limitation of
  the metric and of the planner, rather than a free win from smaller budgets.
* **Memory** (`negotiate_mem0`) makes little difference to this planner, because it reasons mostly
  from open threads and current state, not from episodic facts. An LLM strategist would be expected
  to depend on memory more. That remains to be measured.
* **Invalid-action rate** counts proposals refused by pre-validation or the server. For the
  strategist conditions it is dominated by alliance offers to contestants who are secretly allied
  (hidden information the agent cannot know) and by negotiation-limit refusals. Rule-based bots
  rarely issue refusable actions, so their rate is lower by construction.
* Ten seeds per condition is a small sample. Treat differences of a few percentage points as noise.

## Impostor-mode balance

All-bot matches on Moonfall Isle with the rule-based impostor-mode bots (no LLM), 20 seeds per
field size, 9-minute limit, measured on this repository's code. Reproduce with:

```bash
cd backend
uv run python -m arenix.sim.impostor_balance --seeds 20
```

| players | impostors | kill cooldown | impostor wins | avg length | kills | meetings | ejected (impostor / innocent) |
|---|---|---|---|---|---|---|---|
| 5 | 1 | 38 s | 45% | 258 s | 2.0 | 1.7 | 11 / 0 |
| 6 | 1 | 20 s | 50% | 314 s | 3.2 | 2.3 | 8 / 0 |
| 7 | 2 | 80 s | 45% | 281 s | 2.3 | 1.9 | 14 / 1 |
| 8 | 2 | 46 s | 55% | 269 s | 3.2 | 1.9 | 16 / 6 |
| 9 | 2 | 28 s | 45% | 301 s | 3.8 | 2.2 | 20 / 5 |
| 10 | 2 | 24 s | 40% | 366 s | 4.1 | 2.9 | 22 / 8 |

How the numbers were used: the kill cooldown per field size (`KILL_COOLDOWN_S_BY_FIELD` in
`backend/arenix/engine/roles.py`) was adjusted until the impostor win rate sat near 50% at
every size. With 20 seeds the uncertainty is about ±11 percentage points, so the remaining
differences between sizes are within noise. A second impostor joins at 7 players, which is why
the cooldown jumps there and then falls as the field grows.

Caveats: these are bots playing bots. Bot islanders deduce only from what they saw (sightings,
witnessed tasks and kills, skill clues, weighted chat claims), and bot impostors strike only when
nobody is within 10 tiles of the victim or 11 tiles of themselves. Human players lie, coordinate
and miss things differently, so treat this as a starting point for tuning, not a guarantee.
